# AI 教练摘要：自动片段与准确性反馈

## 使用流程

1. 导入 XRK 和本地视频，在单圈分析中选择视频实际对应的遥测圈。
2. 完成并人工核对同步，再进入 **AI 教练摘要**。
3. 查看前三快有效圈的 Sector 表和累计时间差。不同 Sector 的优胜圈不会相加形成虚构目标圈。
4. 观看自动挑选的候选片段；默认四秒，可切换到完整弯道和下游。参考视频需要对照圈自身的校准，不能借用目标圈偏移。
5. 每段回答 **系统挑选的复盘片段是否精准？**：准确、部分准确、不准确、无法判断。
6. 可补充偏早、偏晚、不是这个弯、太短、与建议无关或同步不确定，再提交。显示保存成功后才算收到了反馈。

## 自动片段不可用时：人工选片

1. 在 AI 教练摘要选择真实参考圈和目标圈。自动参考默认来自 Top 3；手动选择仍必须通过现有质量门。
2. 左侧是参考快圈，右侧是目标圈。点击任一侧 **添加 / 调整片段**，可单独选择该圈的本地视频，无须等待自动识别。
3. 播放或拖动时间轴，使用 **设为起点 / 设为终点**；也可输入秒数并以 0.1 秒按钮微调。当前允许 0.1–120 秒的有效片段。
4. 不确定同步时直接 **应用人工片段**，先观看预览。此时不显示对应遥测数值，也只能提交“无法判断”。
5. 要联动遥测，先选弯道入口、最低速度位置、出口或下游终点，找到视频中确实对应的位置，点击 **绑定当前画面与所选位置**，核对圈号后勾选确认。整个片段必须映射到该圈连续、真实的遥测范围。
6. 应用后可查看随播放变化的 GPS 速度和 RPM、联动距离游标。**两侧从起点播放**按各自时间播放，不伸缩片段。
7. 人工片段的评价问题是 **人工修正后的片段是否对应这个弯？**，与原自动片段准确性分开保存；可随时 **恢复自动片段**。

人工片段、圈号、文件大小/修改时间等身份信息和锚点保存在本浏览器，每个圈/区间最多保留十次修正元数据。刷新后需要重新选择同一本地视频；视频本身不会持久化或上传。换圈不会把旧圈校准自动套到新圈，另一侧不变的圈可以继续保留自己的视频。

## 如何挑选

- 使用后端已通过质量门的真实 Top 3 圈与现有弯道区间，不改分析内核。
- 一个弯使用一条真实对照圈，按整个弯道及下游耗时选择；不是拼接最快局部。
- 按目标圈相对对照圈的时间差排序，最多三段，避免重叠弯道重复展示。
- 默认预览围绕目标圈最低速度点；完整上下文使用真实边界穿越时间。
- 弯内、下游及合计时间差均显示正负号含义。这些是观察到的差异，不是因果结论或提升承诺。
- 原有 Top 3 共识支持圈仅作来源说明，并不表示这次片段已获人工确认。

## 反馈与隐私

- 中英文切换；播放后可评价。未确认同步的人工预览仅能选择“无法判断”，不能计为准确片段。
- 反馈按片段、目标/参考圈、同步和时间范围区分；同一条可修改，失败可重试。
- 仅发送选择、可选原因、圈号、片段时间、版本和不透明标识；人工修正还携带原片段关联和锚点时间/距离，不发送视频或文件名。
- 统计按 `selection_source=automatic/manual` 与 `side=reference/target` 分组，人工修正不能覆盖原自动投票，也不计入自动成功率。旧客户端字段保持兼容。
- 反馈存入 Railway 现有 SQLite，和教练对驾驶行为的确认标注分开。
- 当前匿名反馈不是已验证训练标签，不自动改变筛选规则或训练模型。

## 当前限制

- 仍需人工核对视频属于哪一圈及同步准确性。系统负责定位候选，不要求车手从整段视频重新筛选。
- 双侧可分别选文件，也可复用当前载入的视频，但必须分别核对圈号和校准；没有快圈画面时仍可只用真实遥测对照。
- 当前人工同步使用一个可核对锚点，不估计时钟漂移。短片中若仍观察到错位，应调整或取消确认，不能把勾选当作算法已验证。
- 人工裁剪不更改上方完整公共弯道/下游的遥测差值；剪辑时长之差不能替代圈速或区间收益。仅覆盖部分弯道时有单独提示。
- 双视频按各自片段起点同时播放，尚不是逐帧同距离锁定。
- 四秒是网页本地播放范围，不是上传到服务器或自动生成的 GIF/MP4 文件。
- 真实文件本地验收只证明解析、播放和反馈流程工作；测试锚点不等于视频/遥测配对真值。
- 首批收集反馈后，应由教练复核错选原因，再决定规则调整。不得把点赞比例直接当检测准确率。
